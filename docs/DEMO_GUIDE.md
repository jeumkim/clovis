# 3분 데모 가이드

## 데모 전 준비

1. `python run_local.py`로 두 서버를 실행합니다.
2. Receiver와 Sender 페이지가 열리는지 확인합니다.
3. 루트 `.env`에 AI 키와 모델을 설정한 후 서버를 재시작합니다.
4. Receiver 상단 상태가 `AI 연결됨`, 결과 카드가 `실제 AI`인지 확인합니다.
5. 이전 승인으로 DB 값이 바뀌었을 수 있으므로 변경이 남아 있는 예시를 먼저 확인합니다.
6. 유사 사례는 `데모 사례`임을 발표 중 한 번 명확히 설명합니다.

## 3분 시연 시나리오

### 0:00~0:25 — 문제와 범위

“DoCX-AI가 물류 변경 메일을 분류한 이후부터 시작합니다. 저희는 변경 탐지, DB 대조,
위험 판단, 승인, 회신과 보고를 하나의 업무 흐름으로 연결했습니다.”

### 0:25~0:55 — 변경 메일 분석

1. 수신 워크벤치에서 `복합 변경 문의` 또는 변경이 남아 있는 예시를 선택합니다.
2. `변경사항 분석 및 대응안 생성`을 클릭합니다.
3. 상단 파이프라인이 추출과 DB 대조 단계로 이동하는 것을 보여줍니다.

### 0:55~1:35 — 의사결정

1. 위험 점수와 판단 이유를 보여줍니다.
2. DB 기존값·변경값·메일 원문 근거를 짚습니다.
3. 추천 대응안 3개 중 하나를 선택합니다.
4. “승인 전에는 DB가 바뀌지 않는다”는 점을 말합니다.

### 1:35~2:15 — 회신·보고 생성

1. `선택 대응안으로 회신·보고서 생성`을 클릭합니다.
2. 영문 파트너 회신과 한국어 내부 보고가 동시에 생성되는 것을 보여줍니다.
3. `발신 스튜디오로 넘기기`를 클릭합니다.

### 2:15~2:45 — Communication Guard

1. 수신 분석 컨텍스트가 발신 화면 왼쪽에 유지되는 것을 보여줍니다.
2. 두 초안을 수정할 수 있음을 보여줍니다.
3. `담당자 최종 검토 완료`를 눌러 준비도가 100%가 되는 것을 보여줍니다.
4. TXT 저장 또는 복사 기능을 보여줍니다.

### 2:45~3:00 — 마무리

“CLOVIS는 메일을 읽어주는 AI가 아니라, 근거와 담당자 통제를 유지하면서 물류 변경을
실제 실행 가능한 의사결정으로 바꾸는 운영 레이어입니다.”

## 데모 실패 대비

- AI 응답이 느리거나 실패하면 화면에 오류/폴백 상태가 표시됩니다. 발표에서는 준비된 실제
  AI 결과 캡처를 보조 자료로 사용하고, 라이브 흐름은 안전 폴백으로 계속 시연합니다.
- 포트 8765가 안 열리면 Sender 서버, 8766이면 Receiver 서버 로그를 확인합니다.
- 특정 예시가 이미 승인되어 변경 없음으로 나오면 다른 예시를 선택합니다.
- 실제 메일 발송은 하지 않으며 복사/TXT 저장까지가 MVP 범위라고 설명합니다.

- [ ] Communication Guard 100% 화면
- [ ] 우선순위 대시보드 또는 변경 이력
