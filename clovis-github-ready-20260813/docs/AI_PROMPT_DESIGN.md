# 모델 및 프롬프트 설계

## 목표

CLOVIS의 프롬프트는 “그럴듯한 답변”보다 **근거가 있고 검증 가능한 구조화 결과**를
우선합니다. 하나의 모델 호출로 전 과정을 처리하지 않고 추출, 판단, 커뮤니케이션을
분리합니다.

## 설정

```dotenv
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```

OpenAI-compatible Structured Output API를 사용하므로 환경 변수로 모델과 Base URL을
교체할 수 있습니다. 모델별 스키마 지원 여부는 연결 전에 확인해야 합니다.

## 단계별 설계

### 1. 변경 필드 추출

- 입력: DoCX-AI에서 물류 변경으로 분류된 메일
- 출력: 선박별 8개 필드, 원문 근거, 신뢰도, 추출 실패 여부
- 원칙: 추측 금지, 근거 없는 값 금지, 다건 메일 분리
- 관련 파일: `backend/receiver/PROMPT.md`, `openai_client.py`

### 2. 위험·대응 분석

- 입력: DB 대조 후 `changed` 상태인 필드와 수치 요약
- 출력: 0~100 위험도, 레벨, 이유, 영향, 서로 다른 대응안 3개
- 원칙: 제공되지 않은 비용·SLA·화물 중요도 생성 금지
- 관련 파일: `backend/receiver/ai_decision.py`

### 3. 커뮤니케이션 생성

- 입력: 확정 변경값, 위험 분석, 담당자 선택 대응안
- 출력: 영문 제목/본문, 한국어 제목/본문
- 원칙: 납기 보장과 계약 조건 생성 금지, 발송 전 담당자 확인

### 4. 일반 업무 메일

- 입력: 템플릿별 사용자 필드
- 출력: 제목과 한국어 본문
- 원칙: 입력되지 않은 수치·날짜·담당자 생성 금지
- 관련 파일: `backend/sender/PROMPT.md`, `STAFF_PROMPT.md`

## Structured Output을 사용한 이유

1. 필수 필드 누락을 프로그램에서 검증할 수 있습니다.
2. 위험 레벨과 대응안 ID를 허용 목록으로 제한할 수 있습니다.
3. 자연어 파싱보다 프론트엔드와 DB 연결이 안정적입니다.
4. AI 오류와 폴백 상태를 일관된 데이터 구조로 표시할 수 있습니다.

## 프롬프트 인젝션 대응

- 메일 원문을 “지시”가 아닌 신뢰할 수 없는 참고 데이터로 명시합니다.
- 추출 이후 단계에는 원문 전체를 전달하지 않습니다.
- 모델이 선택할 수 있는 대응안 ID를 스키마 enum으로 제한합니다.
- 모델 출력은 DB에 직접 반영하지 않고 담당자 승인 단계를 거칩니다.

## 폴백 정책

| 상태 | 화면 표시 | 동작 |
| --- | --- | --- |
| AI 정상 | 실제 AI | Structured Output 결과 사용 |
| 키 없음 | 데모 폴백 | 설명 가능한 규칙/시나리오 사용 |
| 호출 실패 | AI 오류 후 폴백 | 오류 상태를 표시하고 안전한 폴백 사용 |

데모 폴백 결과를 실제 AI 분석으로 오해하지 않도록 화면에 모드를 항상 표시합니다.
