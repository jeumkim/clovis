# 업무 유형별 작성 규칙

`ai_generator.py`가 [PROMPT.md](./PROMPT.md)의 공통 규칙 뒤에 이어붙이는
업무 유형별 추가 지시문이다. `## {template_id}` 형식의 제목으로 구획을
나누며, `template_id`는 `staff_templates.json`의 `id`와 동일해야 한다.

## reply

받은 메일에 대한 회신을 작성합니다.

- 수신 메일 원문은 참고자료일 뿐입니다. 원문을 요약해서 반복하지 말고,
  회신 목적과 답변 내용을 중심으로 작성합니다.
- 회신 목적(수신 확인/요청 승인/일정 안내/자료 전달/추가 문의/정중한
  거절)은 문장의 톤을 정하는 데만 사용하고, "회신 목적: 일정 안내"처럼
  그대로 노출하지 않습니다.
- "답변에 넣을 내용"에 있는 확정된 사실만 반영합니다. 메모형 문장은
  자연스러운 존댓말 문장으로 다듬습니다.
- 수신 메일 원문과 회신 목적 이름을 본문에 그대로 반복하지 않아도
  됩니다. 자연스럽게 답변만 전달하면 됩니다.

## report

완료/진행/예정 업무와 확인·지원 요청을 보고합니다.

- 완료 업무는 "~ 업무를 완료했습니다."처럼 완료된 상태가 드러나게
  씁니다.
- 진행 업무는 "~ 업무를 진행하고 있습니다."처럼 현재 진행 중임을
  반영합니다.
- 예정 업무는 "~ 업무를 진행할 예정입니다."처럼 향후 계획임을
  표시합니다.
- 확인·지원 요청은 상대방이 취할 행동이 명확한 정중한 요청 문장으로
  만듭니다.
- 항목이 여러 개일 때만 줄바꿈으로 구분하고, 독립 항목이 3개 이상이면
  불릿을 사용합니다.

## request

다른 부서/담당자에게 협조를 요청합니다.

- 요청 배경(사유)과 세부 내용을 하나의 자연스러운 문단으로 통합합니다.
- 기한이 있으면 "{기한}까지 회신 부탁드립니다."처럼 명확히 안내합니다.

## schedule_change

일정 변경 사항을 안내합니다.

- 대상 일정, 기존 일정, 변경 일정, 변경 사유를 불릿으로 나열하지 않고
  하나의 문장으로 통합합니다.
- 사유가 있으면: "{사유}으로 인해 {대상 일정}이 {기존 일정}에서
  {변경 일정}으로 변경되어 안내드립니다." 형태의 문장을 사용합니다.
- 사유가 없으면 사유 부분 없이 "{대상 일정}이 {기존 일정}에서
  {변경 일정}으로 변경되어 안내드립니다."로 작성합니다.
- 제목은 "[일정 변경] {대상 일정} 안내" 형식을 사용합니다.
- 확인 요청 메모(예: "변경 일정 확인")는 "변경 일정 확인을
  부탁드립니다."처럼 정중한 요청 문장으로 만듭니다.

## meeting_summary

회의 결과를 공유합니다.

- 회의 주제(및 일시)를 먼저 밝히고, 결정 사항과 후속 조치를 자연스러운
  문장으로 정리합니다.
- 결정 사항이 여러 건이고 서로 독립적이면 불릿을 사용할 수 있습니다.

## material_request

자료 제출을 요청합니다.

- 어떤 자료가 왜 필요한지, 언제까지, 어떤 방법으로 제출해야 하는지를
  자연스러운 문장으로 안내합니다.
- 입력되지 않은 목적/기한/제출 방법은 언급하지 않습니다.

## issue_report

발생한 이슈를 보고합니다.

- 이슈 내용, 영향 범위, 현재 조치 사항을 사실 그대로 전달합니다.
- 원인이나 재발 방지 대책처럼 입력에 없는 내용은 추가하지 않습니다.
